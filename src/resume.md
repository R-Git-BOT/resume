## 職務要約

サーバーサイドエンジニアとして、PHPおよびC#を中心に、メタバース・オンラインゲームのバックエンド、バーチャルイベントプラットフォーム、業務支援Webアプリケーション、既存システムのモダナイゼーションに携わってきました。

バックエンド開発では、Web API、リアルタイム通信、ゲームロジック、DB・マスタ設計、外部サービス連携、分析ログ、テスト、不具合調査まで幅広く担当しています。特に、最大8人が同時参加するオンラインゲーム内ミニゲームでは、Unityクライアントからの通信受信、サーバー上の状態更新、DBへの永続化、クライアントへの配信まで、サーバーサイド領域を初期開発からリリース後の運用改修まで一貫して担当しました。

また、バーチャルイベントプラットフォーム開発では、一般ユーザー向けAPI、イベント主催者向けサイト、運営管理ツールを横断して開発し、外部ID認証、EC連携、チケット・アイテム購入、バーチャル空間への入室管理など、サービスの主要機能を実装しました。

既存システムの改修では、仕様書だけでなく、画面動作、コード、DB構造、ログを確認して仕様を把握し、影響範囲を整理したうえで設計・実装へ落とし込むことを重視しています。コードレビュー、設計書レビュー、OJT、環境構築支援、タスク管理にも携わり、担当機能だけでなくチーム全体の品質と進行を支えてきました。

# 主なプロジェクト経験

## 1. メタバース型オンラインゲーム／新規ミニゲームのサーバーサイド開発

### 期間

2023年12月～2024年12月（約13か月）

### プロジェクト概要

アバターを利用して仮想空間内で交流し、複数のアトラクションを遊べるメタバース型ソーシャルオンラインゲームの開発に参画しました。

担当したのは、最大8人が同一ルームで遊ぶ正体隠匿型ミニゲームです。19種類の役職、役職ごとのスキル、投票・再投票、1対1のカードバトル、PvEエネミー、状態異常、イベント、切断・再接続、リマッチなど、多数のゲーム要素を持つリアルタイムゲームでした。

### チーム体制

| 役割 | 人数 |

| バックエンドエンジニア | 1～2名 |
| Unityクライアントエンジニア | 3名 |

### 役割・担当範囲

サーバーサイドエンジニアとして、Web API、リアルタイムゲームロジック、通信プロトコル、DB・マスタ設計、分析ログ、E2Eテストを担当しました。

Unityクライアントからの通信受信、サーバー上でのゲーム状態更新、DBへの永続化、クライアントへのレスポンス・イベント配信まで、サーバーサイド領域を初期開発からリリース後の運用改修まで一貫して担当しました。

- 最大8人のマッチング、ルーム作成、入退室処理

### 課題と対応

#### 複数プロセスを横断する不具合調査

1つのプレイヤー操作が、Unityクライアント、リアルタイム通信サーバー、メッセージ基盤、ゲームループサーバーを横断して処理される構成でした。また、ゲーム進行中の状態は主にメモリ上で管理されるため、事後調査ではログと通信内容が重要でした。

サーバーログ、通信メッセージ、Unityクライアントの挙動を処理経路ごとに照合し、切断・再接続時の状態不整合、スキルの処理順序、リマッチ後の復帰処理などの原因を切り分けました。

#### 状態と処理順序の組み合わせへの対応

19種類の役職、16種類の状態異常、複数のシーンやスキルが相互に影響するため、同時発生時の優先順位や例外条件が多いシステムでした。

仕様だけでは判断できない箇所はプランナーと確認し、ゲームとして成立する挙動を整理してから実装しました。また、プレイヤー操作の競合に対しては、個別にロックを追加するのではなく、ゲームループ内の処理を逐次実行する方式へ変更し、処理順序を保証しました。

#### ルーム単位の可用性向上

ゲームループ内で例外が発生すると、1ルーム全体の進行に影響するため、想定可能な異常系では例外送出を避け、エラーログを記録して処理を継続する方針へ変更しました。

また、放置・離脱ユーザーが存在してもサーバーリソースが残り続けないよう、準備タイムアウト、ルーム有効期限、ゲーム終了、リマッチ成立条件などのライフサイクル処理を実装しました。

#### 秘匿情報の配信制御

役職情報や占い結果など、本人以外へ送信してはいけない情報については、クライアント側の表示制御だけに依存せず、ユーザー単位の個別配信を使用しました。不要なクライアントへデータ自体が届かない構成とすることで、秘匿性を担保しました。

#### テスト環境の整備

ユニットテストが十分に整備されていない環境だったため、実サーバーへ最大8クライアントを同時接続し、マッチングからゲーム終了・リマッチまでを検証するE2Eテストを整備しました。

固定時間の待機ではなく、期待する通信メッセージの受信や状態反映を待つ条件待機方式を実装し、非同期処理を含むテストの安定性を高めました。

### 成果

- 新規ミニゲームのサーバーサイドを、初期実装からリリース、運用改修まで約1年間担当
- Web API、リアルタイムゲームロジック、通信プロトコル、DB、分析ログ、テストを横断して開発
- 約6,000行、40超のテストメソッドからなる8クライアント同時接続E2Eテストを整備・保守
- 切断・再接続、リマッチ、複数スキル同時発生などの不具合を継続的に修正
- ゲームループ内の例外処理、逐次実行化、非同期処理の見直し、同期対象の絞り込みなど、安定性と処理負荷を改善
- ヘルプ参画メンバーへの環境構築支援、OJT、タスク管理、コードレビューを担当

## 2. バーチャルイベントプラットフォームのサーバーサイド開発

### 期間

2022年6月～2023年11月（約1年6か月）

### プロジェクト概要

スマートフォン、PC、VR端末からバーチャル空間のイベントへ参加できる、メタバース型バーチャルイベントプラットフォームの開発に参画しました。

一般ユーザーはアバターでイベントへ参加し、チャット、ボイスチャット、動画・PDFなどのコンテンツ閲覧、チケット・アイテム購入を行います。イベント主催者は専用サイトからイベント、エリア、チケット、出展物を管理し、運営担当者は管理ツールからマスターデータ、アプリバージョン、ログ、商品情報などを管理します。

汎用プラットフォームに加え、外部ECや企業向けID基盤と連携する個別プロダクトの開発にも携わりました。

### 開発体制

複数企業による混成開発チームで、参画期間中のアクティブ開発者は約20名でした。GitLabのマージリクエストを利用したコードレビュー体制で開発を行いました。

### 役割・担当範囲

サーバーサイドエンジニアとして、一般ユーザー向けAPI、イベント主催者向けサイト、運営管理ツール、一部C++リアルタイムサーバーの設計・実装・テスト・不具合修正を担当しました。

### 担当工程

- 詳細設計
- API設計
- DB・テーブル設計
- 実装
- テスト
- 不具合調査・修正
- コードレビュー対応
- リリース対応

### 使用技術と用途

| 技術 | 使用内容 |
| --- | --- |
| PHP 7.4／独自フレームワーク | 一般ユーザー向けAPI、主催者サイト、運営管理ツールの実装 |
| MySQL 8.0／idiorm | ユーザー、マスター、購買、ログなど複数DBへのアクセス |

| Laravel | 関連するチケット販売サイトとのAPI・DB連携 |
| C++ | リアルタイムチャットサーバーの接続管理処理の改修 |
| Docker／Nginx／PHP-FPM | 開発環境およびWebアプリケーション実行環境 |

### 開発した主な機能

#### 外部ID認証・アカウント連携

- 外部ID基盤を利用した認証開始、コールバック、ログインAPI
- JWTの署名、issuer、audience検証
- 新規アカウント作成と既存ゲストアカウントの連携
- 連携済みIDの重複チェックとユーザー属性更新
- 外部サービス向けの所持チケット集約API

#### 外部EC連携

- ECサイトへのシングルサインオンURL生成
- 商品、コレクション情報の取得

- 商品管理用テーブルと運営管理画面

#### チケット・アイテム・課金

- チケット一覧、購入、所持確認、チケットコード連携API
- アイテム購入、使用、所持確認API

#### バーチャル空間・運営機能

- バーチャル空間への入室許可と接続先サーバー情報の返却

- イベント、商品、アプリバージョン、ログ、キャッシュの管理画面
- C++チャットサーバーにおける多重チャンネル参加防止処理

### 課題と対応

#### 複数サービスをまたぐ認証フロー

アプリ、WebView、自社API、外部ID基盤をまたぐ多段の認証フローであったため、Redisに保存したstateの照合とJWT検証を行い、不正または不整合な認証結果を受け付けないようにしました。

既存のゲストアカウントを本アカウントへ連携する際に、アカウント状態や認証情報が正しく更新されない問題については、状態遷移とDB更新処理を見直しました。

#### 外部ECとのデータ整合性

外部ECのWebhookが届かないケースに備え、Webhook処理だけに依存せず、後から商品・購入情報を同期できるフォールバック処理を実装しました。

また、複数プロダクトが同一コードベースを利用していたため、購買ログをプロダクト単位で分離し、既存プロダクトのデータと混在しないようにしました。環境ごとに異なる外部ECの設定値はデータ側で切り替えられる構成としました。

#### 保守性と異常系への対応

複数箇所に分散していたEC連携、CSV出力、ページング処理を共通化し、重複実装を削減しました。

入力値の組み合わせが矛盾する場合のエラー処理、空配列を利用した検索時のエラー回避、無効データを含む場合でも管理画面全体を停止させない表示制御など、異常系を考慮した実装を行いました。

### 成果

- 約1年6か月の参画期間で、API、主催者サイト、運営管理ツールを横断して開発
- 関連リポジトリで約650コミット、79本の作業ブランチを作成
- 新規APIエンドポイント15本以上、新規DBテーブル8件、管理系ページ・機能7件以上を実装
- 外部ID認証、EC連携、チケット・課金、入室管理など、サービスの主要機能を担当
- 外部ID認証およびEC連携機能を本番環境へのリリースまで担当

- 脆弱性診断の指摘に基づくAPI改修や、既存機能の不具合修正に対応

# 自己PR

## 複雑な仕様を整理し、バックエンド処理へ落とし込む力

オンラインゲーム開発では、複数の役職、スキル、状態異常、シーン進行、切断・再接続が相互に影響する処理を担当しました。仕様書だけでは判断できない条件をプランナーと整理し、処理順序、状態遷移、通信対象を明確にしたうえで実装しています。

Webアプリケーション開発でも、既存仕様、DB構造、外部サービスの制約を確認し、API、DB更新、異常系を含めた実装へ落とし込んできました。

## システム全体を確認した不具合調査

サーバー側のコードだけで判断せず、通信メッセージ、DB更新状況、ログ、UnityクライアントやWeb画面の挙動を照合し、再現条件と原因箇所を切り分けることを重視しています。

リアルタイム分散システムにおける接続断や状態不整合、外部認証・EC連携におけるデータ不整合など、複数のコンポーネントをまたぐ問題へ対応してきました。

## 設計・レビュー・メンバー支援を含めた開発経験

自身の実装だけでなく、コードレビュー、設計書レビュー、環境構築支援、OJT、タスク管理を経験しています。担当範囲や判断理由を他メンバーへ説明し、チーム内で同じ方針に沿って開発できる状態を整えることを意識しています。

今後は、サーバーサイド領域を軸に、API・DB設計、実装、テスト、運用改善まで継続的に関わり、保守性・拡張性を意識したプロダクト開発経験を深めていきたいと考えています。
