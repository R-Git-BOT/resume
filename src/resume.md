## 1. メタバース型オンラインゲーム／新規ミニゲームのサーバーサイド開発

| 項目 | 内容 |
| --- | --- |
| 期間 | 2023年12月～2024年12月（約13か月） |
| 体制 | 6～7名（BE 1～2名、Unity 3名、プランナー1名、デザイナー1名） |
| 役割 | サーバーサイドエンジニア |
| 技術 | C#、.NET 8、ASP.NET Core、MagicOnion、NATS、LogicLooper、MySQL、Redis、Docker、Azure Data Explorer |

最大8人で遊ぶ正体隠匿型ミニゲームについて、Web API、リアルタイムゲームロジック、通信プロトコル、DB・マスタ設計、分析ログ、E2Eテストを担当しました。19種類の役職、16種類の状態異常、投票、カードバトル、PvE、切断・再接続、リマッチなどを実装し、初期開発からリリース後の運用改修まで一貫して対応しました。

**課題・Action・成果**  
複数操作の同時発生による処理競合や、例外によるルーム停止が課題でした。ゲームループ内の処理を逐次実行へ変更し、想定可能な異常系ではログを残して処理を継続するよう改善しました。また、Unity、gRPC、NATS、ゲームループを横断する切断・再接続不具合をログと通信内容から切り分けて修正しました。最大8クライアントを接続するE2Eテストを整備し、主要フローのリグレッション検知に活用しました。

**主な実績**

- 対象機能でHTTP API 29本、gRPCメッセージ92本、内部メッセージ94本を使用
- Web API、ゲームロジック、通信プロトコルの関連リポジトリで約1,300コミット
- コードレビュー、環境構築支援、OJT、タスク管理を担当

# 自己PR

## 複雑な仕様をバックエンド実装へ落とし込む力

オンラインゲーム開発では、役職、スキル、状態異常、切断・再接続が相互に影響する処理を担当しました。仕様書だけで判断できない条件を関係者と整理し、処理順序、状態遷移、通信対象を明確にしたうえで実装しています。Web開発でも、既存仕様、DB構造、外部サービスの制約を確認し、正常系・異常系を含むAPIやDB処理へ落とし込んできました。

## システム全体を確認した問題解決とチーム支援

サーバー側だけで判断せず、通信メッセージ、DB、ログ、UnityクライアントやWeb画面の挙動を照合して原因を切り分けることを重視しています。また、コード・設計書レビュー、環境構築支援、OJT、タスク管理を経験しており、自身の実装だけでなく、チーム全体が同じ方針で開発できる状態づくりにも取り組んできました。

## 多種多様な案件に対し安定したクオリティを確保できる対応力

これまで経験した案件の多くは1年以内にクローズとなる比較的小さい案件で、短期間で使用技術・業界・対応領域が大きく変化する環境の中で設計・実装などを対応していました。どんな使用技術であれ、まず調査を進め、自分の担当領域に関する知識を入れて仕事を進めるように心がけています。新しい案件に対してすぐ動き、すぐ適用し、結果に導けるのが強みです。
